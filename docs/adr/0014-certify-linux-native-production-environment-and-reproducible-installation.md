# 认证 Linux 原生生产环境与可复现安装

Status: Accepted
Date: 2026-07-25

## 背景

直播拆条依赖 Python、FFmpeg、ffprobe、fontconfig、中文字体和 TLS 等多项系统能力。
仅记录版本号或直接从源码安装，无法证明候选构建物在生产主机上具备一致的媒体处理
能力，也难以复现安装结果和发布证据。

## 决定

我们采用单一的 Linux 原生生产认证基线，并以预构建 wheel、固定依赖、已记录的
Ubuntu archive snapshot、非交互幂等安装脚本和严格环境预检构成可复现安装路径。
预检既校验版本和安装身份，也实际验证媒体、字体、TLS、workspace 与原子文件操作
能力，并在首次远程业务请求前一次报告全部已发现问题。

当前认证平台、版本范围、构建物、安装顺序和预检要求以
[生产就绪规格第 4 节](../production-readiness-spec.md#4-生产环境与安装)为准。

## 权衡

该决定缩小了可以称为生产环境的平台范围，并增加了构建、依赖锁定和安装证据的
维护成本。作为交换，生产版本不再依赖主机上的隐式状态，安装失败能在处理用户内容
和调用供应商之前暴露，候选构建物也可以在相同基线上复验。

## 后果

- 只有通过认证基线和严格预检的安装才能用于生产交付；其他平台仍可用于开发，
  但不构成生产认证。
- 生产机不得从 Git checkout、sdist 或 editable install 构建或导入应用。
- 系统包、wheel、锁文件及其摘要成为发布证据的一部分，任何构建物变化都会形成
  新的候选版本。
