# 收敛 live-only 公共接口与受管 workspace

Status: Accepted
Date: 2026-07-25

## 背景

同时保留多种业务命令、兼容参数和可任意拼接的输出路径，会让同一直播拆条请求
产生多套行为，也无法可靠判断哪些目录由应用拥有、哪些交付物可以覆盖或清理。
宽松配置与隐式上下文来源还会使生效契约难以校验和审计。

## 决定

我们将业务命令收敛为单个 `live` 入口，并保留独立的 `cache clear` 管理命令。
素材旁文件、默认 workspace、显式 workspace、覆盖发布和缓存清理均采用固定语义；
应用只管理带有效标记的 workspace，并在规范化路径、目录所有权、运行锁和原子发布
约束下操作。配置与课程上下文在进入业务模块前完成严格校验，形成独立且不可变的
本次运行输入。

公共命令、路径与 workspace 契约以
[生产就绪规格第 5 节](../production-readiness-spec.md#5-公共-cli-契约)为准，
配置和课程上下文契约以
[生产就绪规格第 6 节](../production-readiness-spec.md#6-配置与课程上下文)为准。

## 权衡

该决定明确放弃旧命令、旧参数、旧目录布局和隐藏兼容路径，既有调用方需要改用
新的单一接口。作为交换，CLI、skill 调度器和操作员面对同一套可验证契约，应用
可以安全地区分素材、处理缓存、运行诊断、当前交付和上一版交付。

## 后果

- `live` 成为唯一业务入口，旧业务命令和兼容参数不再属于公共接口。
- 非空但没有有效标记的目录不会被接管、覆盖或清理。
- `cache clear` 只清理受管缓存，不创建直播拆条运行，也不触碰诊断或交付。
- CLI 底座与 skill 调度器必须使用同一套严格配置、课程上下文和 workspace 语义。
