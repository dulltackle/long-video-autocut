# 采用单一组合根与业务能力深模块

Status: Accepted
Date: 2026-07-25
Amends: [CLI 负责视频处理，skill 负责上层调度](0008-keep-video-processing-in-cli-and-use-skill-for-orchestration.md)

## 背景

既有决定已经把核心视频处理放在 CLI 底座、把协作流程放在 skill 调度器，但尚未
规定生产依赖从何处装配、业务事实由谁拥有，以及测试替身可以在哪些边界注入。
如果模块直接读取全局配置、环境变量或其他模块内部状态，CLI 内部仍会形成隐式耦合，
难以独立验证失败、不变量和供应商替换。

## 决定

我们保留 CLI 底座与 skill 调度器的职责边界，并进一步采用单一组合根装配生产
Adapter、配置、媒体能力、处理缓存和运行诊断。顶层应用只按显式阶段协调深模块；
每个业务能力模块拥有自己的类型化输入输出、业务校验、算法版本和事实，跨模块通过
小而稳定的接口传递不可变结果。真实存在变化的外部能力才暴露 Adapter seam，测试
组合根在同一接口上装配确定性实现。

模块边界、依赖方向、事实所有权、装配顺序和目标包布局以
[生产就绪规格第 8 节](../production-readiness-spec.md#8-生产模块组合)为准。

## 权衡

该决定增加了类型化契约和组合根的显式装配工作，也限制了从任意位置替换内部实现
的自由。作为交换，供应商与基础设施细节被收进深模块，顶层编排保持稳定，测试可以
沿公开接口验证行为而无需 Mock 模块内部函数。

## 后果

- 生产依赖只能在单一组合根注册，业务模块不得自行选择 Adapter 或读取全局状态。
- 模块之间保持单向依赖，不共享可变业务对象，也不泄漏供应商响应和物理缓存路径。
- skill 调度器继续负责上层协作，不承载 CLI 底座的核心业务算法。
- 生产组合根和测试组合根必须满足相同的顶层接口契约。
