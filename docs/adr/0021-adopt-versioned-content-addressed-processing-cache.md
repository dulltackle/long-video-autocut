# 采用版本化内容寻址处理缓存

Status: Accepted
Date: 2026-07-25
Amends: [处理缓存必须包含影响结果的输入摘要](0009-cache-live-processing-results-with-result-affecting-inputs.md)

## 背景

既有决定只要求缓存键包含影响结果的输入摘要，没有明确身份由谁定义、算法与 schema 如何演进、并发计算如何收敛，以及损坏或写入失败应如何处理。生产运行需要在路径、运行标识和无关配置变化时稳定复用结果，同时在任何影响结果的输入或算法变化后可靠失效。

## 决定

采用共享、版本化、内容寻址的处理缓存。整场转写、识别分片、主题评审和字幕优化分别拥有独立命名空间；相应业务模块拥有身份文档、payload schema、算法版本和业务校验，缓存仓库只拥有统一 envelope、摘要、物理布局、可取消单航班、不可变发布、损坏隔离和通用诊断。

缓存身份使用标准化 PCM 或规范化 JSON 计算 SHA-256，并只包含会影响结果的事实和版本。有效条目以临时文件、文件同步、原子重命名和父目录同步发布；同一身份并发计算由跨线程、跨进程锁收敛。当前完整契约见[生产就绪规格 §10](../production-readiness-spec.md#10-处理缓存)。

## 权衡

每个业务模块都必须维护明确的身份与 payload 版本，缓存实现也需要锁、摘要校验和耐久写入，增加了设计与测试成本；作为交换，缓存失效可解释、并发复跑确定，且不会因程序版本、文件路径或运行诊断变化无谓丢失命中。

## 后果

- 只缓存完整且通过业务校验的成功结果；有效条目不可修改，也不设置 TTL。
- 版本或身份不匹配按未命中处理；内容损坏先隔离再重算。
- 权限、锁、磁盘、同步或原子发布失败属于本地处理失败，不得伪装成普通未命中。
