# 以分层验收证据批准生产版本

Status: Accepted
Date: 2026-07-25

## 背景

确定性自动测试能够证明算法、模块接口和故障语义，却不能单独证明真实供应商、
真实中文素材、媒体工具和人工内容质量可用。反之，仅执行一次真实端到端运行既
难以复现，也无法系统覆盖失败与恢复路径。若不同门禁使用不同构建物，验收证据
还会失去共同的候选身份。

## 决定

由 commit SHA 与候选 wheel 摘要共同锁定唯一候选，并让同一构建物依次通过完整
无密钥自动门禁、故障注入、安装与 CLI 黑盒验收、独立交付校验、真实供应商冷
运行、零请求缓存复跑和人工内容复核。全部证据通过后，才允许创建版本一致的签名
annotated tag 和绑定该候选的发布记录。

当前门禁、证据和生产版本批准契约以
[生产就绪规格第 14 节](../production-readiness-spec.md#14-生产验收矩阵)为准。

## 权衡

- 分层门禁增加了发布周期、认证环境和人工复核成本，但分别覆盖确定性故障语义、
  真实集成行为、缓存可复用性与内容质量，不能由单一层级替代。
- 测试以模块接口和稳定 seam 为 surface，不设置覆盖率百分比门槛或绑定所有内部
  辅助函数，避免用脆弱指标替代契约证据。
- 真实凭据只在受控人工门禁中注入，降低了日常 CI 风险，也使真实门禁不能完全
  无人值守。

## 后果

- 候选代码或 wheel 的任何变化都会使既有证据失效，全部门禁必须针对新候选重新
  执行。
- 自动门禁必须零失败、零错误、零跳过且不使用测试级重试；硬门禁不能以备注或
  手工豁免放行。
- 只有已归类的供应商短暂故障或认证主机基础设施故障可以复跑同一不可变候选；
  生产 tag、发布证据和候选构建物必须保持可校验的一致绑定。
