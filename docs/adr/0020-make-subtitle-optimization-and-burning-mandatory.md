# 将字幕优化与烧录设为强制生产路径

Status: Accepted
Date: 2026-07-25
Supersedes: [短视频默认烧录字幕并过滤纯语气词](0010-burn-subtitles-and-filter-filler-words-for-clips.md), [用大模型在子序列约束下优化短视频字幕](0011-optimize-clip-subtitles-with-llm-under-subsequence-constraint.md), [分段字幕优化窗口以提升子序列通过率](0012-segment-subtitle-optimization-window-to-improve-subsequence-pass-rate.md)

## 背景

既有字幕决定保留了关闭烧录、优化失败后导出无烧录字幕视频、旁挂规则 SRT 和人工复核回退。这些路径会让未满足字幕质量要求的短视频仍被当作成功交付，与“发布就绪短视频”和标准交付物的生产语义冲突。

## 决定

字幕优化与烧录是每条待发布短视频不可跳过的生产路径。`SubtitleOptimization` 在短视频窗口内按字符预算组织连续文本，以只允许删除字符的抽取式提示生成原文子序列，校验后将字幕显示块对齐到逐字时间；缺少逐字时间时使用确定性时间回退。优化结果是 `DeliveryBuild` 烧录字幕的必需输入。

任何子窗口的请求、校验或时间对齐失败都会使整个字幕优化阶段及本次直播拆条运行失败，不返回部分结果；生产配置不提供关闭字幕优化、关闭烧录或规则字幕降级交付的开关，也不生成短视频旁挂字幕。当前契约见[生产就绪规格 §9.4](../production-readiness-spec.md#94-主题评审与字幕优化)。

## 权衡

强制依赖文本模型会提高供应商故障对整次运行可用性的影响，也要求失败后重跑；它换取了单一、可验证的发布就绪标准，避免操作员在成功交付中辨认降级短视频或承担隐式人工返工。

## 后果

- 成功交付的每条短视频都使用通过校验和对齐的优化字幕完成烧录。
- 字幕优化不再以规则过滤、旁挂字幕或人工复核作为成功回退；规则处理仅可用于诊断和确定性测试。
- 有效空结果仍可成功且不调用字幕模型；非空结果中任一字幕工作项失败均不产生新标准交付物。
