# 采用全有或全无的直播拆条运行状态机

Status: Accepted
Date: 2026-07-25
Supersedes: [语音识别失败中止，主题评审失败只输出未评审方案](0007-stop-on-transcription-failure-but-continue-planning-without-topic-review.md)

## 背景

旧决定允许主题评审失败后输出未评审方案，并保留显式导出未评审结果的兼容路径。
这会把供应商或处理失败与合法的零短视频结果混在一起，也可能让不完整处理被误认为
可交付成功，无法形成唯一、可审计的生产终态。

## 决定

我们采用全有或全无的直播拆条运行状态机。只有主题评审、字幕优化、交付构建、
完整性验证和原子发布全部成功，直播拆条运行才成功；完成完整主题评审但没有发布
就绪短视频是可发布完整标准交付物的有效空结果。提交点之前的任何失败或中断都不得
产生新标准交付物，只保留已验证并原子写入的处理缓存和脱敏运行诊断包。

不可协商的成功与失败语义以
[生产就绪规格第 3 节](../production-readiness-spec.md#3-不可协商的生产语义)为准，
阶段、终态、退出码、中断和清理规则以
[生产就绪规格第 7 节](../production-readiness-spec.md#7-直播拆条运行生命周期)为准。

## 权衡

该决定以交付正确性和终态可解释性优先于部分结果可用性。主题评审或字幕优化的
暂时故障会使整次运行失败，而不会降级生成看似可发布的结果；作为交换，操作员可以
明确区分有效空结果、处理失败和中断，任何成功交付都满足同一质量门槛。

## 后果

- 不再存在未评审导出、字幕降级交付或部分交付成功路径。
- 每个稳定故障都必须映射为类型化错误、稳定退出码和可审计终态。
- 失败与中断必须清理敏感临时文件并保护既有交付，不能撤销有效缓存。
- 发布提交点之后运行视为成功；诊断收尾故障只能标记诊断不完整，不能撤销交付。
