# 直播拆条运行进度界面规格

> 归档来源：[GitHub Issue #65：实现直播拆条运行进度界面](https://github.com/dulltackle/long-video-autocut/issues/65)。决策地图与各决策票链接保留在下文“补充说明”中。

## 问题陈述

操作员目前无法用一个稳定、易读且实时优先的界面判断指定 `.autocut` 工作区中的直播拆条运行已经走到哪个阶段、此前各阶段形成了什么结果，以及失败、中断、诊断不完整或记录损坏时下一步应如何理解。结构化事件日志是运行中的权威事实来源，但它是追加写入的机器记录；运行诊断清单只在终止时原子形成，不能支撑实时观测。直接读取终端文本、文件修改时间或原始 JSON 都会迫使操作员和前端重新解释领域语义，并可能把长静默误判为进程失活、把中间零值误判为有效空结果，或泄露不应展示的路径与诊断内容。

仓库还缺少一份可复现的前端源码、稳定的只读 HTTP 边界和覆盖桌面／窄屏的已验证交互实现。现有真实样本全部失败，从候选规划开始的五个阶段没有真实样本，因此首版还必须明确区分真实观察、确定性契约验证和仅有代码推断的证据等级，不能以伪进度填补未知。

## 解决方案

在仓库内实现一个独立开发工具：启动时接收单个受管 `.autocut` 工作区，由仅使用 Python 标准库的只读服务安全读取并聚合结构化事件日志、运行诊断清单和仍被保留的标准交付物，向 Vite + React 前端提供版本化的运行索引、单次直播拆条运行观测快照和受管短视频媒体端点。

界面采用已验证的“阶段控制台”方向，以可横向浏览的九阶段时间线为主轴，让实时观测和历史回看共用同一界面。浏览器每秒通过强 ETag 条件轮询已形成的事实，不解析原始事件、不推断进程存活、不自动改变操作员当前选择。失败和中断提供分层、安全、只读的诊断解释；只有越过发布提交点且匹配的标准交付物仍被保留时才开放短视频就地预览。

该工具不成为 CLI 底座的新公共入口，不修改直播拆条运行，不进入生产 wheel、生产安装、发布构建物或生产版本门禁。

## 用户故事

1. 作为开发者，我希望用一个明确的 Python 模块命令指定单个 `.autocut` 工作区启动工具，从而无需修改 CLI 底座或手工拼装多个进程。
2. 作为开发者，我希望启动器拒绝非受管工作区、不安全路径、符号链接和非普通文件，从而只观察应用拥有且可安全读取的数据。
3. 作为开发者，我希望默认在本机 loopback 和固定用户端口提供界面，从而得到开箱即用且不向局域网暴露的开发体验。
4. 作为远端开发者，我希望可以显式选择已约定的 WireGuard 监听模式，从而通过受信对端查看运行而不新增应用令牌。
5. 作为操作员，我希望在界面先打开、直播拆条运行后启动时仍能自动发现新运行，从而不必刷新整个页面。
6. 作为操作员，我希望看到工作区内全部已发现的直播拆条运行，从而能在当前观测与历史回看之间切换。
7. 作为操作员，我希望运行列表按首条可信事件的启动时间倒序排列，从而最新运行稳定地位于前面。
8. 作为操作员，我希望无法取得可信启动时间的记录沉底且不按目录修改时间或运行标识猜测顺序，从而不会得到伪造的时间关系。
9. 作为操作员，我希望运行列表显示启动时间、直播拆条运行观测状态、阶段、耗时、最后事件时间、可取得完整值的缩短运行标识和诊断完整性，从而能识别目标运行。
10. 作为操作员，我希望首次打开时选择 URL 显式指定的运行，否则选择最新可识别运行，从而快速进入预期上下文。
11. 作为操作员，我希望手动选择运行后，新运行只更新列表而不抢占详情，从而阅读和排查不被打断。
12. 作为操作员，我希望实时观测与已终止运行共用同一运行列表、详情和时间线，从而不需要理解“实时／历史”两套模式。
13. 作为操作员，我希望直播拆条运行观测状态严格区分已成功、已失败、已中断、状态未闭合和记录损坏，从而只看到已有证据支持的结论。
14. 作为操作员，我希望状态未闭合不会被描述为仍在处理或已经崩溃，从而长时间没有事件时不会收到无依据判断。
15. 作为操作员，我希望诊断完整性与业务终态分开显示，从而能理解“已成功但诊断不完整”等合法组合。
16. 作为操作员，我希望追加中的半行事件暂时显示为事件尾部未闭合，并在后续轮询完成后自动收敛，从而不会把正常并发写入误判为损坏。
17. 作为操作员，我希望遇到完整坏行、未知事件、序号断裂或运行标识不一致时只保留损坏点前的可信事实并标示记录损坏，从而不消费不可信尾部。
18. 作为操作员，我希望始终看到初始化、预检、素材分析、语音识别、候选规划、主题评审、交付构建、交付验证和发布九个阶段，从而形成稳定的流程心智模型。
19. 作为操作员，我希望阶段节点用图标、文字、边框和受限语义色共同表达未开始、进行中、成功、失败和中断，从而不依赖颜色理解状态。
20. 作为操作员，我希望每个阶段只呈现一条主结论和最多三项辅助事实，同时把状态与耗时放在固定外框，从而快速扫描且不过载。
21. 作为操作员，我希望选中的阶段在实时更新时保持不变，新阶段开始只出现非打断式提示，从而阅读位置不会跳动。
22. 作为操作员，我希望初始化阶段显示直播拆条运行已经初始化和 CLI 底座版本，而不显示恒为未知的生产版本占位，从而只看到有意义事实。
23. 作为操作员，我希望预检阶段显示认证平台、Python、FFmpeg／FFprobe、字体和三项供应商能力选择，从而理解运行环境与生效依赖。
24. 作为操作员，我希望素材分析阶段显示素材时长、文件大小和是否提供课程上下文，从而确认输入分析结果。
25. 作为操作员，我希望语音识别阶段显示转写文本块数、语音覆盖补转次数、整场转写处理缓存事实、请求活动和重试，从而看到已有进展而不虚构识别分片总数。
26. 作为操作员，我希望候选规划阶段显示形成的候选片段数，从而知道这一阶段的实际业务结果。
27. 作为操作员，我希望主题评审阶段显示已评审候选片段数、处理缓存观察、已完成／在飞请求与重试，从而理解已形成的评审事实而不猜测发布就绪数量或淘汰分布。
28. 作为操作员，我希望交付构建阶段显示短视频数量、已形成的标准交付物角色、字幕优化处理缓存和模型请求事实，从而理解构建结果而不把批量文件事件伪装成逐条进度。
29. 作为操作员，我希望交付验证阶段显示已验证项目总数、角色和短视频数量，从而确认独立验证结果而不看到虚假的逐项进度。
30. 作为操作员，我希望发布阶段区分提交事实、普通发布成功和有效空结果，从而只在成功终态成立后看到“有效空结果”。
31. 作为操作员，我希望没有可靠分母时不显示百分比、进度条或预计剩余时间，从而不会把活动计数误读为完成比例。
32. 作为操作员，我希望处理缓存只作为事后事实，重试和退避只描述已记录安排，从而不会被误导为本阶段一定很快或仍在等待。
33. 作为操作员，我希望已失败运行同时通过运行级横幅和失败阶段节点呈现，从而一眼看到总体原因并能定位发生阶段。
34. 作为操作员，我希望只有可信运行诊断清单确认主错误和关联错误，从而日志中的第一条错误不会被错误提升为正式结论。
35. 作为操作员，我希望运行诊断清单迟到时在原位置收敛出已确认主错误，并以非打断方式通知，从而保持阅读、滚动和焦点上下文。
36. 作为操作员，我希望错误详情只展示安全消息、稳定错误分类、白名单诊断和固定中文动作建议，从而获得可行动信息而不泄露敏感上下文。
37. 作为操作员，我希望已中断使用中性终态表达，恢复或清理不完整另行警告，从而不会把中断误称为业务失败。
38. 作为操作员，我希望能够复制经过白名单约束的诊断摘要，从而方便协作排查而不复制原始事件、绝对路径或工作区媒体内容。
39. 作为操作员，我希望交付构建完成后先看到可信短视频数量、验证完成后看到已验证状态，从而知道标准交付物的形成进度。
40. 作为操作员，我希望只有越过发布提交点且匹配运行标识的当前或上一版标准交付物仍存在时才出现预览，从而不会播放未发布或错配媒体。
41. 作为操作员，我希望有效空结果不显示预览入口，从而不会面对无意义的空播放器。
42. 作为操作员，我希望已发布标准交付物不再保留或目录清单不可读取时看到明确的不可预览原因，从而不把媒体缺失误认为运行失败。
43. 作为操作员，我希望按开始时间浏览短视频的标题、主题名、摘要和时长并就地播放，从而无需离开运行上下文核对结果。
44. 作为操作员，我希望单条媒体缺失、变化或路径不安全时只降级该条预览，从而其他有效短视频仍可查看。
45. 作为操作员，我希望播放器支持定位所需的单段字节范围请求且不自动播放，从而可以可靠预览长媒体并避免意外发声。
46. 作为桌面操作员，我希望九阶段轨道位于顶部、运行摘要和短视频预览以固定宽浮层覆盖而不推动轨道，从而保持空间关系稳定。
47. 作为窄屏操作员，我希望九阶段轨道保持横向滚动，运行列表和短视频预览使用全屏抽屉／浮层，从而不把阶段压成难读卡片。
48. 作为键盘用户，我希望 Escape、点外部、选择和关闭操作可预测，浮层关闭后恢复触发器焦点和滚动位置，从而完整使用界面。
49. 作为操作员，我希望页面可见时约一秒内看到已完整落盘的新事实、页面隐藏时暂停轮询并在恢复时立即刷新，从而兼顾及时性和资源消耗。
50. 作为操作员，我希望终态详情停止周期轮询、运行索引继续刷新，并在详情 ETag 变化时补取一次，从而既减少无效请求又能收敛迟到诊断和媒体变化。
51. 作为操作员，我希望未知字段可在同一兼容版本内被忽略，但未知判别值或不兼容版本明确显示界面不兼容，从而避免猜测性降级。
52. 作为安全负责人，我希望服务只返回语义投影和受管媒体，不暴露原始结构化事件日志、整个工作区、绝对路径、文件摘要、供应商 endpoint 或异常文本，从而维持既有白名单披露边界。
53. 作为维护者，我希望工具的 Python 与前端依赖、构建产物和 CI 与生产包严格分离，从而不改变生产版本批准证据或发布表面。
54. 作为维护者，我希望首版对所有消费字段保留证据来源，并在普通成功真实运行可用后做非阻塞复核，从而发现代码推断与实际事件节奏的偏差。

## 实现决策

1. **工具边界**：实现为仓库内独立开发工具，模块名为 `tools.live_progress`。它不得成为 `video-auto-editor` 公共命令、不得导入生产包的私有实现，也不得进入生产 wheel、发布构建物、生产安装或 ADR-0025 门禁。既有无源码、不可复现且被忽略的旧前端构建残留应删除，不作为实现参考。
2. **启动契约**：唯一启动入口为 `python -m tools.live_progress WORKSPACE`。`WORKSPACE` 是唯一必填位置参数，必须指向单个受管 `.autocut` 工作区；启动时规范化为绝对路径并执行普通文件、no-follow、所有权和受管边界验证。默认 loopback 端口为 `4173`。
3. **进程与构建监管**：日常模式由 Python 服务在同一 origin 提供静态前端和 `/api/v1/`。启动器对 Web 源码、公共资源、配置、包清单、锁文件和 Node 主版本计算内容摘要；构建缺失或摘要不一致时重新构建，否则复用本地构建。启动器不得自动联网安装依赖，缺依赖时只给出明确的 `npm ci` 提示。开发模式仍由同一 Python 入口监管 Vite 与 API，Vite 代理 `/api`。
4. **工具链**：Python 服务只使用 Python 3.12 标准库，不增加生产或工具侧第三方 Python 依赖。前端基线为 Node 24、npm 11、Vite 8、React 19，提交精确 lockfile，并通过 engine、package manager 和开发引擎声明锁定契约。只跟踪源码、配置、静态源资源和包清单；依赖目录与构建产物不入库。
5. **网络边界**：默认仅绑定 loopback。WireGuard 日常模式只绑定 `10.8.0.5`，只允许来源 `10.8.0.3`；不监听 `0.0.0.0`、普通局域网或 Docker 网桥。WireGuard 提供传输加密与对端认证，不新增 Cookie、Bearer Token、签名 URL 或媒体密钥。显式的 `--dev --listen wireguard` 允许 Vite 直接绑定 `10.8.0.5:4173`，并必须警告它依赖“只有可信开发对端可达”的拓扑假设。CORS 仅允许配置中的前端来源且不启用凭据。
6. **服务端聚合**：Python 服务把结构化事件日志、运行诊断清单和匹配的已发布标准交付物投影为稳定语义；React 不读取原始事件、不解释运行诊断包、不拼接工作区路径。结构化事件日志是实时权威来源，运行诊断清单只补充终态、主错误和关联错误，标准交付物只签发发布成功与预览能力。
7. **文件快照语义**：请求时检查文件身份、大小和纳秒级修改时间；无变化可复用聚合快照，有变化则从头完整重读，不维护 byte offset 或游标。单个结构化事件日志上限固定为 64 MiB。尾部无换行片段不解析；首个完整坏行、未知 schema／字段／事件码、序号断裂或运行标识不一致会终止可信前缀。符号链接、不可读文件、运行目录不安全和读取期间身份变化均不得降级为可信事实。
8. **API 版本与标量**：JSON 资源使用 `live_progress.v1`，成功响应为 UTF-8 JSON。时间为 UTC RFC 3339 毫秒；时长、序号、数量和字节数为非负整数且拒绝布尔值；运行标识为 `run_` 加小写 UUIDv4；判别值采用封闭 snake_case。所有对象拒绝重复字段、非有限数字和不属于当前联合分支的字段。同版本未知对象成员可忽略；未知判别值或不兼容版本必须停止解释并显示“界面版本不兼容”。
9. **缺席事实**：所有可缺席值使用三态 Presence：`available` 携带值，`not_observed` 表示该事实尚未形成，`not_applicable` 表示当前分支不适用。不得用 `null`、空字符串或业务零值代替缺席；空数组是可用事实，与未观察到不同。
10. **ETag**：每个 JSON 资源以确定性序列化形成覆盖精确响应字节的强 ETag；`If-None-Match` 命中返回无正文 `304`。运行索引中的 `snapshot_etag` 与对应详情响应的 HTTP ETag 完全一致。服务端不返回当前时间等会让无事实变化响应持续变化的字段。
11. **运行索引资源**：`GET /api/v1/runs` 返回顶层版本和 `runs`。每项包含运行标识、五态直播拆条运行观测状态、Presence 形式的启动时间／阶段／耗时／最后事件时间、诊断完整性及详情 ETag。按首条可信事件时间倒序，时间相同按完整运行标识升序；无可信启动时间者沉底后按完整标识升序。不分页，不返回目录 mtime、排序键、进程存活布尔值或预裁切短标识。
12. **观测快照资源**：`GET /api/v1/runs/{run_id}` 返回版本、运行标识、运行观测、诊断完整性、Presence 形式的最可信终态、固定九阶段快照、错误集合和标准交付物快照。终态事实包含证据来源、结果、结束时间、耗时、退出码、结果种类和中断信号；只返回当前最可信证据。
13. **终态优先级**：匹配运行标识的已发布标准交付物可独立确认成功；否则由可信时间线末尾唯一终态事件或完整运行诊断清单确认成功、失败或中断。错误事件和中断请求本身不能确认终态。无终态时，损坏或不可用记录为 `record_corrupt`，其余为 `unclosed`；任何状态都不得解释为进程仍存活。
14. **诊断完整性**：诊断状态封闭为 `complete`、`incomplete`、`corrupt`、`unavailable`，并始终返回已验证事件数。完整对应 `valid`；不完整覆盖事件日志缺失、事件尾部未闭合、终态事件缺失和运行诊断清单缺失；损坏覆盖编码、JSON、重复字段、非有限数字、schema、未知事件／字段、序号、运行标识和运行诊断清单与事件摘要不一致；不可用覆盖超限、符号链接、不可读和不安全运行目录。已发现运行的这些数据问题以 `200` 观测资源表达，而不是伪装成 HTTP 传输失败。
15. **九阶段生命周期**：响应始终按初始化、预检、素材分析、语音识别、候选规划、主题评审、交付构建、交付验证、发布的固定顺序返回九项。普通阶段生命周期为未开始、进行中、成功、失败或中断，时间与终态耗时只来自匹配的可信阶段事件；初始化的正常成功是只含观测时间的特殊检查点。进行中耗时由前端根据启动时间近似显示，不进入 API ETag。
16. **阶段事实归属**：每个阶段包含公共生命周期、阶段专属 `result`、阶段专属 `progress` 和所属错误标识。状态和耗时不占“一条主结论 + 最多三项辅助事实”的额度。请求、重试、退避和处理缓存事实即使阶段失败或中断仍保留，但不得解释成比例或剩余时间。只有成功阶段的业务计数可以从 `work_item_count` 投影；常量计数和失败／中断的强制零不得展示。
17. **初始化、预检与素材分析**：初始化结果只投影应用版本。预检结果投影认证平台、Python／FFmpeg／FFprobe 版本、字体可用性以及语音识别／主题评审／字幕优化三项供应商能力选择，推进事实只表达配置已观察和环境结果。素材分析结果投影字节长度、时长和是否提供课程上下文；没有伪进度。
18. **语音识别与候选规划**：语音识别结果投影成功转写文本块数、覆盖补转次数和整场转写处理缓存命中／未命中，推进事实投影已完成请求数、在飞请求数、传输重试数和最近退避安排；不得投影识别分片总数、请求总数、语音覆盖百分比或 ETA。候选规划只投影成功形成的候选片段数，进行中只显示中性动作。
19. **主题评审**：结果投影已评审候选片段数和处理缓存命中／未命中计数，推进事实投影请求完成数、在飞数、传输重试数和最近退避安排。不得提供发布就绪数量、淘汰原因分布、相邻候选批次总数、完成百分比或 ETA。
20. **交付构建与验证**：交付构建结果投影短视频数、按标准交付物角色聚合的已创建项目和字幕优化处理缓存观察；推进事实只描述字幕优化请求／重试和交付状态。文件事件在末尾批量出现，不得渲染逐条导出进度。交付验证结果投影已验证项目数、短视频数和角色聚合；推进事实只描述验证状态，不得渲染逐项完成进度。
21. **发布**：发布结果只投影 `commit_observed`、`published` 或 `valid_empty`。前者表示已观察到发布提交事实但运行终态尚未闭合；后两者需要成功终态证据。运行结果、退出码和结果种类保留在运行终态，不复制到阶段。中间零数量不得命名为有效空结果。
22. **标准交付物角色**：角色聚合固定包含交付运行清单、转写 JSON、转写 SRT、拆条方案、元数据、拆条报告和短视频七类非负计数；只有完整批量事实形成后才可用。
23. **错误契约**：错误集合按稳定错误标识索引，错误事实包含错误码、类别、阶段、模块、可选操作标识、事件序号、安全消息、新运行资格、八种固定操作员动作和按错误码白名单验证的诊断。禁止原始事件、自由结构对象、绝对路径、文件摘要、endpoint、内部源码位置和异常文本。阶段按事件顺序引用自己的错误标识。
24. **主错误与动作建议**：只有验证通过的运行诊断清单可签发主错误、关联错误和恢复不完整；只有事件日志时不猜测主错误。动作固定映射为修正配置、安装或升级依赖、检查输入素材、检查供应商凭据、稍后再试、释放磁盘空间、检查发布备份、报告内部错误。新运行资格只渲染为“完成处置后可开启新的直播拆条运行”或“不要直接重新运行”，不提供写操作按钮或扩写未承诺教程。
25. **标准交付物快照**：状态封闭覆盖未观察、构建中、等待验证、验证失败、已验证、发布中、发布失败、已发布和有效空结果；短视频数量使用 Presence。构建成功可显示可信数量，验证成功可显示已验证，但预览能力只能在越过发布提交点后形成。
26. **预览能力**：服务只检查当前和上一版标准交付物，严格验证交付运行清单、运行标识、元数据、角色、引用、逻辑路径和字节长度，不扫描其他目录。预览状态区分未就绪、因标准交付物未保留／目录清单不可读／无效而不可用、不适用和可用。有效空结果为不适用。结构化事件日志损坏不自动撤销可独立验证的已发布预览能力。
27. **短视频目录**：短视频按开始时间升序，同时间按短视频标识升序。每项只返回短视频标识、主题名、标题、摘要、开始／结束／时长及媒体能力；不暴露候选来源、关键词、同主题系列、清单路径、逻辑路径、物理位置或文件摘要。媒体异常仅降级单条，原因封闭为缺失、不可读、已变化或不安全路径。
28. **媒体端点**：稳定端点为 `GET|HEAD /api/v1/runs/{run_id}/short-videos/{short_video_id}/media`。支持完整 GET／HEAD 与一个 `bytes` 范围，返回正确的 `200`、`206`、`304`、`404`、`410`、`416`、`Content-Type: video/mp4`、`Accept-Ranges`、`Content-Length`、强 ETag 和必要的 `Content-Range`。不实现多范围、multipart、`If-Range` 或动态转码。每次打开时 no-follow 并再次校验身份与长度，ETag 使用已发布清单摘要而不是重复哈希整段媒体。
29. **HTTP 错误**：JSON 错误信封同样携带版本，只含稳定码和安全中文消息。JSON 端点只定义无效请求、运行不存在、方法不允许和内部错误；不得回显异常、路径或请求参数。未知媒体为 `404`，曾形成资格但已不保留或发生漂移为 `410`。
30. **轮询与选择状态**：页面可见时每秒分别条件轮询运行索引与当前非终态详情；隐藏时暂停，恢复后立即刷新。终态详情停止周期轮询，但索引继续；索引中详情 ETag 变化时再条件获取一次以收敛迟到运行诊断清单或媒体保留变化。运行标识可存入 URL 查询参数；API 不保存会话状态。服务器只承诺每次打开所得的有界文件快照，不承诺跨文件事务快照，也不在单次请求内循环追平。
31. **视觉层级**：采用已验证的 B“阶段控制台”。TopBar 后先放可横向滚动的九阶段轨道，再放运行详情。运行摘要为可折叠按钮：桌面为 760px 锚定浮层，窄屏为全屏抽屉；轨道不得位移。选中阶段用强边框，生命周期同时使用图标、文字和受限语义色。
32. **详情与预览交互**：主详情显示阶段结论与最多三项辅助事实，技术详情原位展开；右侧只显示供应商请求、重试／退避和处理缓存等语义事实，不伪装原始日志。失败横幅或标准交付物摘要固定在详情顶部。桌面预览使用 520px 固定右侧浮层，窄屏使用全屏浮层；禁止 autoplay，关闭后恢复焦点和滚动位置。
33. **响应式与可访问性**：桌面和窄屏均不得产生页面级横向溢出；窄屏九阶段轨道自身可横向滚动。浮层支持 Escape、点外部和显式关闭；状态不得只靠整块底色表达。实时更新必须保持选中阶段、阅读位置和键盘焦点。
34. **规格归档与 CI**：在仓库文档中归档同一规格并链接已关闭的决策地图及各决策票，不新增 ADR 或领域词。新增仅覆盖独立工具的路径限定 CI，执行 Python 单元测试、前端 lint、独立类型检查、Vitest／React Testing Library 测试和构建；现有无密钥生产门禁、架构校验与文档校验不改变，也不增加路径跳过。

## 测试决策

1. **测试原则**：测试只断言外部可观察行为、版本化契约、安全边界和用户交互，不绑定私有函数、React 组件拆分、内部缓存结构或 HTTP handler 的实现细节。优先使用最高接缝，只有无法经济覆盖的封闭判别和故障矩阵才下沉。
2. **主测试接缝**：首选一条端到端黑盒链路——在临时受管工作区准备确定性直播拆条运行事实，通过正式 Python 启动入口拉起服务，使用真实 HTTP 请求验证 API，再用已构建 React 应用和 Playwright 验证代表性桌面与窄屏流程。这一条接缝覆盖工作区发现、服务端投影、ETag、轮询、状态收敛、布局和交互。
3. **服务端契约测试**：在工具本地使用标准库 `unittest`，以序列化的结构化事件日志、运行诊断清单和标准交付物夹具验证运行索引、观测快照、Presence、九阶段顺序、终态优先级、确定性 JSON、强 ETag 与错误信封。测试对 HTTP／DTO 断言，不 Mock 内部聚合辅助函数。
4. **生产发射证据**：扩展既有确定性直播拆条端到端测试，证明前端消费的每个字段至少具有现行 schema／读取器依据和一次真实生产组合根发射。普通成功与有效空结果都必须形成可供观测投影读取的确定性夹具；仅有未执行代码推断的字段不得成为界面承诺。
5. **阶段覆盖矩阵**：初始化、预检、素材分析和语音识别复用现有运行诊断生命周期与读取器先例；候选规划、主题评审、交付构建、交付验证和发布补齐成功／失败的确定性端到端发射断言。另覆盖转写成功计数、整场转写处理缓存命中、语音覆盖补转、主题评审请求与处理缓存、字幕优化请求与处理缓存、标准交付物角色、发布提交、普通成功和有效空结果。
6. **损坏与并发读取**：覆盖缺失日志、半行随后补全、首个完整坏行、未知字段／事件码、重复字段、非有限数字、序号断裂、运行标识不一致、64 MiB 上限、不可读文件、符号链接、非普通文件、读取中身份变化和跨文件竞态。断言只消费可信前缀，且下一轮 ETag 能收敛新事实。
7. **终态与错误**：覆盖已成功／已失败／已中断／状态未闭合／记录损坏五态，发布提交点优先、终态事件和运行诊断清单优先级，运行诊断清单迟到，以及主错误、关联错误、恢复不完整和阶段错误引用。证明没有清单时不猜主错误、不以错误事件或中断请求确认终态、不以时间新鲜度推断存活。
8. **受管媒体测试**：沿用现有交付 capability、发布原子性和工作区树巡检测试的先例，覆盖当前／上一版标准交付物绑定、错配运行标识、有效空结果、标准交付物不再保留、目录清单损坏、局部文件降级、路径逃逸、符号链接、文件变化和 no-follow 打开。HTTP 黑盒覆盖 GET、HEAD、三种单范围、`304`、`404`、`410`、`416` 及所有必需响应头。
9. **前端契约与组件测试**：使用 Vitest 与 React Testing Library 对封闭联合做穷尽渲染，覆盖未知版本／判别值停止解释、运行默认选择与保持选择、终态停止详情轮询、索引触发单次收敛、错误双层呈现、复制诊断摘要白名单、预览资格和局部媒体降级。测试面向可访问名称、文本、焦点和网络契约，不断言组件内部 state。
10. **浏览器验收**：用 Playwright 复验已确认原型行为：桌面运行浮层 760px、预览浮层 520px、打开浮层前后轨道位移为零、窄屏抽屉／预览全屏、页面无横向溢出、九阶段轨道可横向滚动、无 autoplay、Escape／点外部关闭、焦点与滚动恢复、实时更新不抢选中阶段、点击提示才切换当前阶段、失败技术详情原位展开且浏览器控制台无错误。
11. **安全与网络**：验证 loopback 默认监听、WireGuard 日常模式只接受指定来源、拒绝其他绑定和 HTTP 方法、CORS 不带凭据，并证明 API 不披露工作区路径、文件摘要、endpoint、异常文本、原始事件或未批准诊断字段。开发 WireGuard 模式必须验证启动警告而非虚构应用层来源限制。
12. **构建与 CI**：专用 workflow 固定 Node／npm 契约，执行可复现 `npm ci`、lint、类型检查、前端测试、构建和 Python 工具测试。验证构建摘要命中时复用、源码或工具链变化时重建、依赖缺失时只提示安装。构建产物和依赖目录不得进入 Git。
13. **既有测试先例**：沿用仓库已有的 CLI 黑盒验收、确定性组合根直播拆条端到端、运行诊断读取器与生命周期、交付 capability 与原子发布、工作区安全树巡检等测试风格；不通过放宽断言、修改夹具语义、跳过或测试级重试掩盖生产缺陷。
14. **真实样本复核**：首版完成后，以至少一次普通成功的真实直播拆条运行做非阻塞复核；有效空结果在自然取得时补验。真实样本若揭示事件顺序、数量或字段契约偏差，应重开对应决定，但不把真实供应商凭据、费用和人工取样作为本规格的实现前置门槛。

## 范围之外

- 从界面启动、取消、重试、修复或以其他方式修改直播拆条运行。
- 新增或恢复 CLI 底座业务入口，改变 live-only 公共接口或全有或全无的直播拆条运行状态机。
- 修改结构化事件日志、运行诊断清单、标准交付物或生产错误注册表来迎合界面。
- 把工具打入生产 wheel、发布构建物、生产安装脚本、ADR-0025 分层验收证据或操作员生产交付。
- 同时发现多个工作区、集中管理工作区，或允许浏览器提交任意文件系统路径。
- 提供原始结构化事件日志接口、静态暴露整个工作区、显示终端文本或在前端重建事件语义。
- 使用文件修改时间、事件新鲜度或静默阈值判断进程存活、卡死、失败或中断。
- 伪造百分比、进度条、总工作项、剩余时间、主题评审通过数量、淘汰原因分布、逐条导出或逐项验证进度。
- 在发布提交点前开放短视频元数据或媒体，或扫描当前／上一版之外的标准交付物目录猜测媒体。
- 动态转码、多段 Range、multipart、`If-Range`、公开分享 URL、应用令牌或复杂身份系统。
- 独立“实时模式”和“历史模式”、终态专用页面，或新运行自动抢占当前选择。
- 将完整真实成功样本作为规格冻结或首版实现的阻塞门槛。
- 重开现有生产 ADR、增加新的领域概念，或修改 `CONTEXT.md`；若实现发现真实冲突，应停止并显式重开对应决定。

- 启动、工具链、构建和 CI 边界来自 [确定前端目录契约与启动方式](https://github.com/dulltackle/long-video-autocut/issues/55)；数据读取与轮询来自 [确定数据通道与实时刷新语义](https://github.com/dulltackle/long-video-autocut/issues/54)。
- 当前 20 次真实运行全部失败：6 次止于预检，14 次止于语音识别；候选规划起的五个阶段没有真实样本。初始化、预检与素材分析有真实观察；语音识别只有失败和请求活动样本；其余结论依赖代码契约与待补的确定性发射证据。证据等级只属于工程规格，不进入操作员界面。
- 本规格与 ADR-0015 的 live-only 公共接口、ADR-0016 的全有或全无状态机、ADR-0017 的深模块边界、ADR-0022 的验证后原子发布、ADR-0023 的结构化运行诊断、ADR-0024 的白名单披露和 ADR-0025 的生产版本门禁一致，不修改或绕过这些决定。
